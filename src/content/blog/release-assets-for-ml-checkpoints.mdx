ML 프로젝트를 포트폴리오로 보여줄 때 큰 checkpoint를 git history에 직접 넣는 것은 좋지 않습니다.
clone이 무거워지고, 코드 변경과 모델 배포의 경계도 흐려집니다.

`Modulation-aware-key-estimator`는 이 문제를 release asset으로 정리했습니다.

## 바꾼 구조

- repo에는 코드, 문서, 테스트만 남긴다.
- checkpoint는 GitHub Release asset으로 올린다.
- loader는 첫 실행 때 checkpoint를 다운로드한다.
- 다운로드 후 SHA-256을 검증한다.
- 사용자는 별도 설정 없이 CLI/API를 실행한다.

이 구조는 작은 repo와 재현 가능한 모델 배포를 동시에 만족시킵니다.

## 남은 과제

학습 코드, 데이터 manifest, split 기준, 실험 로그를 별도 training surface로 복원해야 합니다.
추론 repo를 깔끔하게 만든 다음에는 모델 provenance를 채우는 일이 다음 단계입니다.
